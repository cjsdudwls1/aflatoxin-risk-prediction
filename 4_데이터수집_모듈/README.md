# 아플라톡신 데이터 수집 모듈

올해 과제를 **새 데이터**로 다시 돌릴 수 있도록, 데이터 수집·가공 과정을
하나의 모듈로 묶었습니다. 주소와 날짜만 있으면 → 좌표를 찾고 → 관측소·기상·토양을
공공데이터포털에서 받아 → 모델이 쓰는 형태(검사별 60일 기상 시계열)로 만들어 줍니다.

> 한마디로: **"주소 + 채취일이 적힌 CSV"를 넣으면, 모델 학습용 표가 나옵니다.**

---

## 1. 이게 왜 필요한가요?

작년 보고서는 농업기상 79개 컬럼짜리 CSV를 썼습니다. 그런데 그 CSV를 만들던
공공 API(상세·연별 엔드포인트)가 **2026년 현재 전부 폐기(404)**되었습니다.
지금 살아있는 건 "월 단위 일별기상" API 하나뿐입니다.

그래서 이 모듈은 **살아있는 API만으로** 작년과 (거의) 똑같은 데이터를 다시
만들어 냅니다. 어떤 컬럼이 정확히 같고, 어떤 컬럼이 미세하게 다른지는
아래 [5. 데이터 매핑표](#5-데이터-매핑표)에 모두 적어 두었습니다.

## 2. 폴더 구조

```
아플라톡신_데이터수집_모듈/
├─ collect.py            ← CLI 진입점 (이것만 실행하면 됩니다)
├─ config.yaml           ← API 키·기본값 (★ 키를 여기에 넣습니다)
├─ config.example.yaml   ← 설정 예시(키 비움). 새 PC에 복사용
├─ requirements.txt      ← 필요한 파이썬 패키지 목록
├─ README.md             ← 이 문서
├─ collector/            ← 실제 로직(패키지)
│  ├─ config.py          · 설정/키 로더
│  ├─ http_util.py       · API 호출 + 오류 자동 감지
│  ├─ mapping.py         · API 필드 ↔ 모델 컬럼 매핑(단일 진실원천)
│  ├─ stations.py        · 관측소 목록 수집
│  ├─ weather.py         · 일별 농업기상 수집
│  ├─ soil.py            · 토양 화학성 수집
│  ├─ geocode.py         · 주소 → 좌표(카카오)
│  └─ combine.py         · 60일 기상 시계열 결합
├─ outputs/              ← 결과 CSV 가 저장되는 곳(자동 생성)
└─ tests/                ← 검수 스크립트
```

## 4. 설정 (config.yaml) — API 키 3종

이 모듈은 키가 **세 종류**입니다. 헷갈리기 쉬우니 표로 정리합니다.

| 키 이름(config) | 어디에 쓰나 | 지금 상태 | 비고 |
|---|---|---|---|
| `agriweather` | 일별기상 + 토양 수집 | **포함됨** | 사용자 발급(공공데이터포털) |
| `station`     | 관측소 목록 수집     | **포함됨** | 보고서에 공개된 공용키 |
| `kakao_rest`  | 주소→좌표 지오코딩   | **비어 있음** | 필요할 때만 발급(아래 참고) |

```yaml
api_keys:
  agriweather: "여기에 발급키"     # 기상·토양
  station:     "여기에 공용키"     # 관측소(보고서 공개키)
  kakao_rest:  ""                  # 주소가 좌표 없이 들어올 때만 필요

defaults:
  window_size: 60     # 60일 결합 윈도우(combine/pipeline 의 --window 기본값)
  n_neighbors: 20     # 가까운 관측소 후보 수(--k 기본값)
  output_dir:  "outputs"
  verify_ssl:  true   # SSL 인증서 검증(기본 켬). 사내 프록시 등 폐쇄망에서만 false
# 참고: 페이지당 수집 행수는 API마다 한계가 달라(토양 ≤200, 기상 월 ≤31)
#       코드에 안전값으로 고정해 둡니다 — 결과 데이터에는 영향이 없습니다.
```

### 왜 키가 두 개(agriweather / station)인가요?

관측소 목록 API는 **새로 발급한 키로는 403(권한없음)**이 납니다(기관 정책).
대신 작년 보고서에 이미 공개된 공용키가 잘 동작합니다. 그래서 관측소만
`station` 키를 따로 씁니다. 기상·토양은 사용자 본인 키(`agriweather`)를 씁니다.

### 카카오 키는 언제 필요한가요? (대부분 불필요)

지오코딩(주소→좌표)은 **시료 CSV에 좌표(`x_coord`,`y_coord`)가 없을 때만**
돕니다. 좌표가 이미 있으면 카카오 키 없이도 전 과정이 돌아갑니다.
좌표가 없고 주소만 있을 때 발급하세요:

1. <https://developers.kakao.com> 로그인 → "내 애플리케이션" 생성
2. 앱 → "REST API 키" 복사 → `config.yaml`의 `kakao_rest` 에 붙여넣기
3. "플랫폼" 설정 불필요(서버 호출). 무료 한도로 충분합니다.

> ⚠️ `config.yaml` 에는 키가 들어 있습니다. 공유 시 주의하세요. 새 PC로 옮길 땐
> 키를 비운 `config.example.yaml` 만 복사하고 키는 직접 넣는 걸 권장합니다.

## 5. 사용법

`collect.py` 하나로 5가지 작업을 합니다. **어디서 실행하든** 결과는 항상
이 모듈 폴더의 `outputs/` 에 저장됩니다.

### (A) 관측소 목록
```powershell
python collect.py stations
# → outputs/농업기상정보_관측소.csv (현재 217곳)
```
> 관측소가 한 페이지(300곳)를 넘어도 끝까지 페이징해 받습니다.
> 올해 관측망이 늘어도 누락 없이 전부 수집됩니다.

### (B) 일별 농업기상
```powershell
# 특정 관측소·특정 월
python collect.py weather --year 2024 --months 6,7 --spots 026002D003
# 전국 관측소 전체(무겁습니다)
python collect.py weather --year 2024 --all-spots
# → outputs/농업기상_raw_2024.csv (받은 원본 18필드)
# → outputs/농업기상정보_2024.csv  (모델용 12컬럼)
```

### (C) 토양 화학성
```powershell
# 법정동코드(STDG_CD)로 그 동네 전체 시료
python collect.py soil --codes 2671025021 --by bjd
# 필지(PNU_CD)로 특정 땅
python collect.py soil --codes 2671025021000050001 --by pnu
# 코드가 많으면 한 줄에 하나씩 적은 CSV 파일로
python collect.py soil --codes-file 코드목록.csv --by bjd
# → outputs/토양화학성.csv
```

### (D) 60일 결합만 (이미 받아둔 CSV 3개로)
```powershell
python collect.py combine `
  --samples 시료.csv --stations 관측소.csv --weather 기상.csv
# → outputs/결합_60일.csv

# 기간·이웃수 바꾸기(생략하면 config 기본값 60일·20곳)
python collect.py combine --samples 시료.csv --stations 관측소.csv `
  --weather 기상.csv --window 90 --k 30
```
> `--window`(결합 기간 일수)·`--k`(가까운 관측소 후보 수)를 생략하면
> `config.yaml` 의 `window_size`/`n_neighbors` 값을 씁니다. `pipeline` 도 동일합니다.

### (E) ★ 파이프라인 — 주소+날짜 CSV 한 방에
```powershell
# 좌표가 있는 경우(카카오 키 불필요)
python collect.py pipeline --samples 시료.csv
# 주소만 있는 경우(카카오 키 필요)
python collect.py pipeline --samples 시료.csv --addr-col 주소
# → outputs/파이프라인_결합_60일.csv
```

`pipeline` 은 내부에서 ① 좌표 확보(필요시 지오코딩) → ② 관측소 수집 →
③ 시료 채취일에 맞는 달의 기상만 골라 수집 → ④ 60일 결합, 을 자동으로 합니다.

#### 입력 CSV 에 꼭 필요한 컬럼
| 컬럼 | 의미 | 없으면 |
|---|---|---|
| `REQEST_DE` | 채취일(예: 2024-06-30) | **필수**(없으면 중단) |
| `x_coord`,`y_coord` | 경도, 위도 | 없으면 `--addr-col` 로 지오코딩 |
| (주소 컬럼) | `--addr-col 주소` 처럼 이름 지정 | 좌표가 있으면 불필요 |

## 6. 데이터 매핑표

### 6-1. 농업기상 (API 필드 → 모델 컬럼)

신뢰도 **OK**=반올림 수준 일치(소수1자리 ±0.1 산발), **APPROX**=정의/결측 차이가 있는 같은 물리량.

| API 필드 | 모델 컬럼 | 의미 | 신뢰도 |
|---|---|---|---|
| `temp` | `tmprt_150` | 1.5m 평균기온 | OK |
| `hghst_Artmp` | `tmprt_150Top` | 1.5m 최고기온 | OK |
| `lowst_Artmp` | `tmprt_150Lwet` | 1.5m 최저기온 | OK |
| `hum` | `hd_150` | 1.5m 상대습도 | **APPROX** |
| `wind` | `arvlty_300` | 풍속 | OK |
| `max_Wind` | `arvlty_300Top` | 최대풍속 | OK |
| `rn` | `afp` | 강수량 | OK |
| `sun_Time` | `sunshn_Time` | 일조시간 | **APPROX** |
| `srqty` | `solrad_Qy` | 일사량 | OK |
| `soil_Wt` | `soil_Mitr_10` | 토양수분(근사) | **APPROX** |

키 컬럼: `stn_Cd`→`obsr_Spot_Code`, `date`→`date_Time`

**APPROX 3종의 차이 사유(중요):**
- `hd_150`(습도): 반올림 수준 미세차(예 78.6 vs 78.5). 사실상 동일.
- `sunshn_Time`(일조): 원본 CSV는 **91.3%가 결측**이었는데 API는 값을 줍니다.
  → 오히려 모듈 쪽이 더 충실합니다.
- `soil_Mitr_10`(토양수분): API `soil_Wt`는 깊이 구분 없는 단일값이라
  "10cm 토양수분" 정의와 정확히 일치하지 않습니다(근사값).

### 6-2. 토양 (API 필드 → 원본 CSV 컬럼)

14개 응답 필드 중 **이름이 다른 건 2개뿐**, 나머지는 그대로입니다.

| API 필드 | 원본 CSV 컬럼 | 의미 |
|---|---|---|
| `Stdg_Cd` | `BJD_Code` | 법정동코드(행정구역 10자리) |
| `ELCD` | `SELC` | 전기전도도(EC, 토양 염류농도) |
| `No` | (삭제) | 페이지 순번이라 모델에 불필요 |

> 실측 검증: 부산 기장군 시료(2671025021)를 받아 원본 CSV 행과 1:1 대조 →
> 13개 값 **완전 일치**(VLDSIA 결측까지 동일).

## 7. "60일 결합"이 뭔가요? (원리 쉽게)

곰팡이독(아플라톡신)은 **수확 전 60일간의 날씨**와 관련이 깊습니다. 그래서
각 시료마다 "채취일 직전 60일치 날씨"를 한 줄로 붙입니다.

1. **가장 가까운 관측소 찾기** — 시료 좌표에서 제일 가까운 관측소를 고릅니다.
   이때 `cKDTree`(케이디 트리)라는 자료구조를 씁니다. 모든 관측소와 거리를
   일일이 재면 느리니까, 좌표 공간을 미리 나눠 두고 **가까운 후보부터 바로**
   꺼내는 방식입니다(전국 200곳을 순식간에).
2. **60일이 빠짐없이 있는지 확인** — 가까워도 그 기간 날씨에 구멍이 있으면
   다음으로 가까운 관측소를 봅니다. (`rolling(60).count()==60` 으로 검사:
   "직전 60칸이 결측 없이 60개면 통과"라는 뜻)
3. **한 줄로 펼치기(flatten)** — 60일 × 10항목(=600칸)을 한 줄로 폅니다.
   컬럼 이름 규칙은 `항목_일차`이고, **`_00`=채취일, `_59`=60일 전**입니다.
   예: `tmprt_150_00` = 채취 당일 기온, `afp_59` = 60일 전 강수량.

이 순서·경계는 작년 보고서 코드와 동일하며, 합성 데이터로 검증했습니다
(`_00`이 채취일, `_59`가 60일 전인지 값으로 확인).

## 8. 검수 결과

작년 데이터(`scraped_data`)와 신규 수집을 컬럼별로 대조한 실제 결과입니다.
**"완전 동일"이 아니라 "반올림 수준 일치"임을 정직하게 적습니다.**

| 항목 | 방법 | 결과 |
|---|---|---|
| 관측소 수집 | 전체 217곳 대조 | **216곳 작년과 동일**, 1곳(017414F020)만 ~60km 이설 → API 현재값 |
| 기상 exact 7컬럼 | 026002D003·2024-06 30일 | 반올림(±0.1) 허용 시 **전부 일치**. afp만 큰비 날(06-22) 53.5→53.0 0.5차 1건 |
| 기상 diff 3컬럼 | 〃 | hd_150 0.2차, sunshn 작년 결측·API 값제공, soil 정의차(근사) — 모두 문서화된 사유대로 |
| 토양 13컬럼 | 2671025021 | 원본 CSV와 **완전 일치**(VLDSIA 결측까지) |
| 60일 결합 | 합성 데이터 | flatten 순서·윈도우 경계 정확(`_00`=채취일, `_59`=60일전) |
| 본문오류 감지 | 잘못된 요청 | 0행 대신 즉시 오류로 알림 |
| 스모크(`test_smoke.py`) | 네트워크 불필요 | import·매핑·결합·지오코딩 4종 통과 |
| 지오코딩 로직(`test_geocode.py`) | 가짜응답(mock)·키 불필요 | 파싱·중복제거·키오류중단·한도초과부분보존·못찾음NaN **7종 통과**(실네트워크 호출만 키 발급 후 확인) |
| 회귀대조(`test_regression.py`) | 작년 데이터 실대조 | 기상·토양·관측소 **3종 PASS**(차이는 위 사유대로 문서화) |
| 독립 코드리뷰 | 별도 컨텍스트 검수 | Critical 0·High 0 / Medium 3건 전부 반영(SSL검증 복원·지오코딩 예외 가시화·죽은 설정 제거) |

> **왜 "완전 동일"이 아닌가요?** 작년 CSV와 API가 각각 소수 첫째자리로 반올림하기
> 때문에, 같은 실제 측정값이라도 표기상 0.1 정도 산발적으로 벌어집니다(예 11.25 →
> 한쪽 11.2, 한쪽 11.3). 강수량 1건의 0.5 차이는 큰비 날의 측정 단위 차이로 보이며,
> 30일 중 1건뿐입니다. 즉 **데이터 출처가 같다는 것은 충분히 확인**되며, 차이는
> 모듈 결함이 아니라 두 소스의 표기 방식 차이입니다.

재현:
```powershell
python tests/test_smoke.py        # 네트워크 없이 빠른 점검
python tests/test_geocode.py      # 지오코딩 로직(가짜응답, 키 불필요)
python tests/test_regression.py   # 작년 데이터와 실제 대조(소량 API 호출)
# scraped_data 위치가 다르면:  $env:SCRAPED_DIR="경로"; python tests/test_regression.py
```

## 9. 자주 막히는 점 (트러블슈팅)

- **토양에서 0행이 나와요** → `Page_Size`가 200을 넘으면 API가 본문에
  `요청 페이지 형식 오류`를 숨겨 보냅니다. 토양은 코드가 자동으로 200으로
  제한하니, 직접 호출 시에도 **200 이하**로 쓰세요.
- **HTTP는 200인데 데이터가 비어요** → 공공 API는 성공(200)처럼 보여도 본문에
  오류코드를 넣는 경우가 있습니다. 이 모듈은 `http_util.check_result()` 가
  본문 결과코드를 검사해 **조용한 0행 대신 즉시 오류**를 내도록 막아 둡니다.
- **관측소가 403 이에요** → `station` 키(공용키)를 쓰세요. 새로 발급한
  `agriweather` 키로는 관측소 API 권한이 없습니다.
- **지오코딩 좌표가 비어요** → 실패를 조용히 넘기지 않고 알립니다. 카카오 키 오류
  (401/403)면 즉시 중단하고, 호출한도 초과(429)면 남은 주소를 멈춰 부분 결과를
  남깁니다. 끝에 "좌표 없는 시료 N행" 경고도 찍습니다(그 행은 기상피처가 빈 채 남음).
- **죽은 엔드포인트** → `InsttWeather/*`, `*YearDayList` 계열은 전부 404입니다.
  살아있는 건 `GnrlWeather/getWeatherMonDayList3` 뿐입니다.
- **결과가 엉뚱한 폴더에 생겨요** → 이제 어디서 실행하든 모듈 폴더의
  `outputs/` 에 저장됩니다(상대경로를 모듈 기준으로 고정).
